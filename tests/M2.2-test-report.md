## 失败项记录（7.2）

### F-1（已修复，本轮复测通过）：权限测试用例自身的账号状态错误
- 清单编号：T-009；任务/功能：未完成首次改密管理员的权限拒绝。
- 测试用例：`tests/integration/test_admin_testcases_api.cpp: test_permissions`。
- 涉及业务函数：`oj::HttpServer::require_admin`（`src/http/server.cpp:590`）、`oj::auth::check_admin`。
- 触发输入/前置：同一测试环境内先调用 `admin_login`（将 admin 密码改为新密码），再以初始密码登录期望得到「未改密管理员」。
- 预期：未改密管理员登录成功并对用例接口返回 403。
- 实际（修复前）：`[FAIL] 未改密管理员登录成功` 等 4 项失败——密码已在前一步被修改，初始密码登录失败。
- 失败断言/日志：`m22_admin_testcases.log`（开发中间态）。
- 分类：**测试缺陷**（测试前置状态设计错误，非生产代码缺陷）。
- 已确认根因：该测试复用了同一 admin 账号且先完成了改密，无法再构造 `reset_pwd_flag=1` 的未改密管理员。
- 修复：将「未改密管理员」场景拆到独立环境 `test_password_change_required`，不调用 `admin_login`，保持 `reset_pwd_flag=1`；未放宽任何业务要求。
- 复测：`oj_admin_testcases_api_test` 149/0；全量回归 23/23 通过。**状态：通过（修复后复测）**。

### F-2（已修复，第二轮复测通过）：缺省 ord 自动追加可超出声明上限
- 清单编号：T-005；任务/功能：新增用例缺省 ord 计算。
- 涉及业务函数：`oj::TestcaseAdminStore::create`（`src/db/testcase_admin.cpp:52`，缺省 ord 分支）。
- 触发输入/前置：某题已存在 `ord=1000000` 的用例，再新增一条不指定 `ord` 的用例。
- 预期：保存的 `ord` 必须落在声明范围 `[0,1000000]`，或明确拒绝（约束冲突）。
- 实际（修复前）：缺省计算 `max(ord)+1 = 1000001` 未做上限检查，会写入越界的 `ord`，与校验规则（显式 `ord>1000000` 返回 `400`）不一致。
- 分类：**实现缺陷**（范围边界不一致）。
- 已确认根因：缺省分支只计算 `max+1`，未复用范围上限。
- 修复：缺省 `max+1` 超过 `kMaxTestcaseOrd` 时返回新状态 `CreateStatus::OrdExhausted`，HTTP 层映射为 `409`（约束冲突），不写入越界值；显式 `ord` 越界仍为 `400`。同步更新 `README.md` 与 `SPEC.md`。
- 复测：`test_ord_cap_boundary`（显式 `1000000` 可保存、显式 `1000001` 400、自动追加耗尽 409 且不写入）通过；`CreateTestcase.OrdRange` 扩充超 64 位无符号边界后通过；全量回归 23/23。**状态：通过（修复后复测）**。

### F-3（已修复，第二轮复测通过）：集成测试遍历临时 JSON 的悬垂引用
- 清单编号：T-004；任务/功能：缺省 ord（含公开样例）场景的列表顺序断言。
- 测试用例：`tests/integration/test_admin_testcases_api.cpp: test_default_ord_with_samples_and_empty`。
- 触发输入/前置：新增含 2 个公开样例的题目后再加 2 条隐藏用例，读取管理员列表并断言 `(ord,id)` 顺序。
- 预期：列表顺序为 `s0,s1,h2,h3`。
- 实际（修复前）：`[FAIL] 列表按 (ord,id) 混合排序`；调试输出显示响应体本身顺序正确，失败源于测试代码。
- 分类：**测试缺陷**（`for (const auto &e : json::parse(body)["testcases"])` 遍历临时 `json` 的成员，临时对象在范围初始化后析构，属悬垂引用/UB）。
- 已确认根因：范围 for 的 `auto&&` 绑定的是临时对象的成员子对象，不触发临时对象生命周期延长。
- 修复：先把 `json::parse` 结果绑定到具名变量再遍历；未改动生产代码。
- 复测：同场景顺序断言通过；判题执行顺序与列表一致断言通过；集成 205/0。**状态：通过（修复后复测）**。
