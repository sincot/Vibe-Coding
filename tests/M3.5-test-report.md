# M3.5 持久化与停止清理测试与回归报告

- 范围：M3.5 持久化与停止清理。核对并完善完整判题结果到 `submissions`/`user_problem_status`
  的映射与序列化；明确缺失指标与未执行测试点的表示；保持短事务一致性与重复保存/计数
  防护；区分客户端断开与服务器取消；统一停止/取消流程并将队列、worker 与判题子进程
  清理接入优雅停止；覆盖成功/CE/WA/RE/TLE/MLE/SYSERR/输出超限/初始化失败/服务取消各
  路径的资源清理与日志。
- 代码状态：
  - 修改 `src/judge/manager.{h,cpp}`：`SubmissionTask` 增加 `task_id`；`JudgeManager`
    分配任务标识并统计「已接收/已完成」；接收/开始/完成（含状态）/取消/排空核对均记录
    带任务标识的日志；`cancel_all()` 仅在首次取消时记录、`shutdown()` 核对计数。
  - 修改 `src/judge/workspace.cpp`：清理失败/路径越界/符号链接删除失败分别记录含具体
    资源路径的日志并保留现场，资源已不存在时静默收尾（可重复执行）。
  - 修改 `src/http/server.{h,cpp}`：`stop()` 明确记录停止顺序与「已接收/已完成」计数及
    停止耗时；超过 30s 预算仅告警（不强制杀线程、不宣称已保存）；收尾日志只输出一次。
  - 新增 `tests/unit/test_m35_cleanup_unit.cpp`、
    `tests/integration/test_m35_persistence_shutdown.cpp`，并注册到 `CMakeLists.txt`。
- 构建方式：`cmake --build build --parallel 1`（单并发，内存受限约定）。
- 回归级别：**阶段全量常规回归**（改动涉及调度器、停止流程、清理与日志）。
- 环境：Linux，约 3.3 GiB 无 Swap，4 vCPU；隔离临时库（`/tmp`）+ 随机端口 + 专用判题
  目录 + 受控执行器/同步门/故障注入 + 少量真实进程。测试前可用内存约 760 MiB。未通过
  耗尽整机内存、填满正式磁盘或大规模并发制造故障；未停止正式服务、未修改正式提交记录。
- 日志：M3.5 集成 `/tmp/opencode/m35_it.log`；调度回归 `/tmp/opencode/sched.log`；
  全量回归由 `ctest -j1` 串行执行。

## 汇总与验证边界

- 全量 CTest 测试项 **36**，通过 **36**，失败 **0**，跳过 **0**，均实际执行；总耗时约 174s。
- 新增：清理单元 **2** 项 gtest；M3.5 集成 **99** 项断言（1 次测试缺陷修复后全通过）。
- 已实现并验证：
  - 完整结果/逐点详情/编译信息/耗时/峰值内存按约定持久化，关闭重开数据库仍可正确读取；
    未采集内存以 `null` 表示、未执行点不写入、不伪装为 0 或通过；AC/失败计数规则不变。
  - 提交与做题状态单事务写入，中途失败整体回滚；锁竞争在有界 `busy_timeout` 内成功或
    明确失败，不永久挂起、不假成功。
  - 每任务恰由 `JudgeManager` 处理一次并交付独立结果通道，正常完成与取消竞争只产生一条
    记录与一次计数；已接收任务在客户端断开后仍继续执行并保存。
  - 停止顺序（cancel_all → 停 HTTP → shutdown 排空 → 关库）无缝衔接，停止中/停止后新
    提交返回 503 不落库；重复/并发停止幂等、不死锁；停止后无遗留子进程与判题目录。
  - `Workspace` 清理失败可定位、保留现场、不误删；失败路径反复执行 fd/线程/内存无持续
    增长。日志带任务标识/提交 ID，不倾倒完整源码与隐藏用例。
- 未验证 / 未在本阶段实现（明确不标记为完成）：
  - M3.6 Rejudge；M4 的 CodeMirror、提交历史/详情、排行榜、完整搜索筛选分页页面浏览。
  - **崩溃保障边界**：判题结果在判题结束后入库，进程被 `SIGKILL` 或整机断电时进行中任务
    可能丢失；退出清理仅在正常停止流程执行，不承诺强制杀死时生效。本阶段未新增持久化
    任务状态或崩溃恢复机制（如需应另行调整数据模型）。
  - 真实图形浏览器渲染未验证（环境无浏览器）；`/opt/oj-tmpfs` 未在本机挂载（无 sudo），
    真实进程验证使用 `/dev/shm` 与临时目录，tmpfs 挂载仍属部署步骤。
  - 产品目标「5 人同时」由既有 `submit_scheduling_api::test_five_users_sustained_concurrency`
    覆盖（15 次真实 ASan 判题，本次回归通过）；更长时间满负载与更高并发未验证。
- 资源观察：构建与测试均单并发/串行；测试前可用约 760 MiB，回归期间未低于约 720 MiB，
  无 OOM、无卡顿。M3.5 集成测试最大常驻内存约 77 MiB（`/usr/bin/time -v` 78656 kB）；
  受控执行器不启动真实编译，真实 ASan 判题集中在既有调度/沙箱回归中受控执行。
- 清理：测试结束后无遗留判题子进程/僵尸进程与 `oj_judge_*` 临时目录。
