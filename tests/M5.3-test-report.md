## 1. 异常/危险行为 → 机制 → 判定 → 清理/恢复 对应关系

| 危险或异常行为 | 限制/检测机制 | 判定依据 | 预期状态 | 清理与恢复 |
|---|---|---|---|---|
| 无输出死循环 | watchdog 单调时钟 + 进程组 SIGKILL | 超过有效单点时限 | 单点 TLE | waitpid 回收、删除任务目录、后续判题正常 |
| 持续无限输出 | 输出有界采集（64KiB）+ watchdog | 超时且持续排空管道 | TLE（截断） | 同上，不因排空无限等待 |
| 累计/全局超限 | 单次判题全局 60s 硬上限 | 剩余全局预算耗尽 | 总体 SYSERR，已执行点保留 | 终止剩余点、不伪造未执行点 |
| 信号崩溃/非零退出 | 结构化 TerminationReason | WIFSIGNALED / 非 0 退出 | RE（即使输出匹配） | 回收、清理、恢复 |
| ASan 越界 / UBSan 不可恢复 | 默认 `-fsanitize=address,undefined -fno-sanitize-recover=all` | 实际退出状态（非 stderr 文本） | RE，保留诊断 | 回收、清理 |
| 用户自打印 Sanitizer 文本 | 退出状态为唯一判据 | 正常退出且输出匹配 | AC（不误判） | — |
| 分配失败/超大申请 | RSS 采样证据（无证据不判 MLE） | 无可靠超限证据 | 非 MLE（RE/WA/AC） | 回收、清理 |
| 受控 RSS 超限 | 20ms 周期 RSS 采样 + SIGKILL | `memory_exceeded` 且峰值 > 上限 | MLE，峰值入逐点结果 | 回收、清理、恢复 |
| stdout 接近/等于/超 64KiB | 采集上限 64KiB，超限标记截断 | `output_truncated` | 超限不判 AC（RE） | 有界采集后正常结束 |
| 超大 stderr / 编译诊断 | stderr 16KiB、诊断 64KiB 有界 | 截断标识 | 不影响 stdout 比对 | 排空后正常结束 |
| 不读取输入 / 提前退出 | poll 非阻塞写入 + EPIPE 处理 | 写入侧 EPIPE/背压 | 正常结束，不挂死 | 回收、清理 |
| 提前关闭 stdin | SIGPIPE 进程级忽略 + EPIPE | 写入失败即收尾 | 请求正常返回 | 服务不因 SIGPIPE 退出 |
| 关闭 stdout / 后代持有管道 | dup2 + 进程组清理 | EOF/进程组终止 | 正常结束不挂死 | 清理进程组 |
| fork / clone / vfork | 运行阶段 seccomp deny | 系统调用返回 EPERM | 无法创建后代 | 有限次尝试零增长 |
| 向宿主进程发信号 | user/PID 命名空间隔离 | kill 权限检查 EPERM | 不能干扰宿主/他人 | 自身回收 |
| 网络 socket/connect | seccomp deny 网络族 | 系统调用失败 | 无法联网 | 正常结束 |
| 读取沙箱外/宿主文件、越权写 | user/mount 命名空间 + chroot 根 + 只读 /box | open 失败/只读 | 隔离而非全禁边界明确 | 宿主文件不被改写 |
| 继承服务密钥/无关 fd | 受控环境 + close_range/有界 close | 环境/fd 不可见 | 不泄露 | — |
| 沙箱初始化失败 | 不降级，返回 launch_error+sandbox_error | SYSERR 诊断 | SYSERR | 无保护执行被拒绝 |
| 编译环境故障 | 父进程解析编译器 + 启动失败区分 | 编译器缺失/不可执行 | SYSERR（非 CE） | 后续判题恢复 |
| 队列满载 | 有界等待队列，锁内原子入队 | 容量耗尽 | 503 JUDGE_QUEUE_FULL，不落库 | 健康检查/题目查询仍响应 |
| 编译许可等待 | CompileGate + 全局预算 + 取消令牌 | deadline/取消 | 全局超时或取消 | 名额 RAII 释放 |
| 服务停止取消 | cancel_all → 取消令牌 → 进程组终止 | 取消标记 | SYSERR（服务停止） | 已接收任务结果先落库 |
| 崩溃/重启 | `in_flight_tasks` 持久化 + 启动恢复 | pending/claimed 扫描 | 重判或标记 interrupted | 不重复计数/不重复 AC |

### F-501 关闭 stdin 场景返回 CE（测试缺陷）

- 编号/任务：T-502 输入输出异常。

- 复测：T-502 通过（AC，< 8s，无遗留），`m53_judge_abuse` 全部 21 项通过。

## 7. 验证边界与未验证项（如实记录）

1. **模拟 vs 真实**：本轮 M5.3 新增测试均为真实进程验证（真实 g++/gcc、真实
   seccomp/命名空间）。`FakeExecutor` 仅存在于既有历史单元测试，不用于本轮结论。
2. **受控危险 vs 未执行破坏性压力**：本轮执行的是**受控样例**（有限时限、有限
   分配、有限次数尝试）。**未执行**真正无约束的 fork 轰炸、宿主机内存耗尽、
   填满共享 tmpfs 测试（T-510 通过环境开关默认跳过，列为未验证）。受控样例通过
   不代表对任意无约束恶意程序都绝对安全。
3. **功能正确 vs 隔离保障范围**：状态分类（TLE/RE/MLE/AC 等）与清理/恢复为功能
   正确性；seccomp/命名空间隔离提供的是**内核能力所及**的边界，受宿主内核配置
   （非特权 userns、AppArmor 等）约束。`/opt/oj-tmpfs` 的真实 tmpfs 挂载与判题
   已于第三轮补充验证（见第 13 节）；系统级持久
   挂载已由第四轮以 systemd mount unit 落地并验证（第 14 节）。
4. **RSS 采样边界**：内存限制通过 **20ms 周期采样 RSS 并终止**实现。判 MLE 仅在
   观测到 `memory_exceeded` 且峰值超过上限时成立；采样间隔内的瞬时超限若在下次
   采样前回落，不保证被检测到。因此“MLE 有证据”成立，但**不能表述为不会发生
   任何瞬时超限**。无 RSS 证据的分配失败/SIGKILL 明确不判 MLE（T-503 覆盖）。
5. **未直接新增的类别**：见第 4.1 节，均由既有测试覆盖并在本轮阶段回归重跑通过。
6. **真实图形浏览器/真机窄屏**：前端相关未验证项沿用各阶段报告，不属 M5.3。

## 13. 第三轮补充：`/opt/oj-tmpfs` 真实 tmpfs 挂载验证

- **背景**：当前用户 `xay`（uid 1002）无 `sudo`，`/opt/oj-tmpfs` 由 root 拥有且为
  `/dev/vda2` 上的普通目录。直接系统级挂载不可行。
- **方法**：利用内核**非特权 user namespace + mount namespace**（
  `unshare -Ur -m`，无需 root），在私有 mount namespace 内于**生产路径
  `/opt/oj-tmpfs`** 挂载真实内核 tmpfs（`size=512m`）。该挂载仅对本次命名空间可见，
  随命名空间退出自动消失，**不产生任何系统级改动**（结束后 `mount` 确认宿主
  `/opt/oj-tmpfs` 仍未挂载、目录为空）。
- **验证 1（判题）**：在命名空间内 `export TMPDIR=/opt/oj-tmpfs` 运行完整
  `./build/oj_sandbox_integration`。其所有 `TempDir` 工作区经
  `std::filesystem::temp_directory_path()`（`test_sandbox_integration.cpp:61`）落在
  该真实 tmpfs 上。**结果：退出码 0，全部沙箱隔离与资源限制集成测试通过**
  （含真实 g++/gcc 编译运行、CPU/内存/输出限制、目录/网络/进程隔离、ASan/UBSan、
  失败路径清理）。日志：`/tmp/opencode/m53_tmpfs_run.log`。
- **验证 2（生产启动路径）**：在命名空间内以
  `OJ_JUDGE_WORKSPACE=/opt/oj-tmpfs` 真实启动 `./build/oj_server`，验证
  `main.cpp:172` 的 `path_is_tmpfs` 检查与 `main.cpp:184` 的
  `LocalExecutor::sandbox_self_test` 通过，随后 `--port 18099` 提供 `/api/health`
  返回 `{"status":"ok"}`，`SIGTERM` 优雅退出（exit 0）。服务日志记录

## 14. 第四轮补充：系统级持久 tmpfs 挂载（systemd mount unit）

- **落地方式**（操作者以 root 执行，方案 C）：创建 systemd mount unit 并
  `systemctl enable --now`。注意 systemd 的规范 unit 名会把路径中的连字符转义，
  对 `/opt/oj-tmpfs` 正确文件名是 **`opt-oj\x2dtmpfs.mount`**（而非
  `opt-oj-tmpfs.mount`，后者 systemd 视为另一个不存在的 unit）。
- **实测状态**：
  - `findmnt /opt/oj-tmpfs` → `tmpfs`，`size=524288k`（512 MiB），`stat -f -c %T` = `tmpfs`；
  - `systemctl show 'opt-oj\x2dtmpfs.mount'` → `UnitFileState=enabled`、
    `ActiveState=active`、`SubState=mounted`、`Where=/opt/oj-tmpfs`；
  - 写入探针成功，工作目录为 `1777`（tmpfs 默认）。
- **端到端验证**（服务默认工作目录即 `/opt/oj-tmpfs`，未设 `OJ_JUDGE_ALLOW_NON_TMPFS`）：
  1. `./build/oj_server --db <临时库> --seed` 导入种子题（exit 0）；
  2. 启动服务，日志 `判题工作目录已就绪: /opt/oj-tmpfs（tmpfs，容量上限 512 MiB）`
     （`main.cpp:214`，晚于 `path_is_tmpfs` 与沙箱自检），`/api/health` 返回
     `{"status":"ok"}`；
  3. 经真实 HTTP 注册/登录后提交三份源码：**AC / WA / CE** 分别返回正确状态
     （提交 #1 AC、#2 WA、#3 CE，`compile_ok` 相应为 true/true/false），真实
     g++ + 沙箱在 `/opt/oj-tmpfs` 上完成编译与运行；
  4. `SIGTERM` 优雅停止，exit 0；工作目录清理干净，无遗留任务目录/子进程；
     可用内存最低约 761 MiB。
- **仍未执行**：真实**重启主机**验证开机自动挂载（TESTING_GUIDE 六.4 禁止擅自
  重启）。当前以 `enabled` + `local-fs.target.wants` 符号链接 + unit 有效作为
  等价证据，重启后的自动挂载属操作侧确认项。

  `tmpfs`（512 MiB）。
