# M3.1 判题任务调度测试与回归报告

- 范围：M3.1 判题任务调度（`JudgeManager` 有界等待队列 + `min(CPU 核数,8)` worker 线程池 +
  每任务独立结果通道 + 队列满载 503 + 同步返回 + 停止排空回收），复用现有 `JudgeEngine` /
  `LocalExecutor` / `SubmitService` 判题与持久化逻辑。
- 代码状态：
  - 新增 `src/judge/manager.{h,cpp}`（调度器）、`tests/unit/test_judge_manager.cpp`、
    `tests/integration/test_submit_scheduling_api.cpp`。
  - 修改 `src/submit/submit.{h,cpp}`（移除全局判题串行锁、新增原始提交时间参数、执行器
    异常转 `SYSERR`、首次 AC 收敛为最早原提交时间）、`src/judge/local_executor.cpp`
    （父进程解析可执行路径后 `execv`，fork 后不做复杂逻辑）、`src/http/server.{h,cpp}`
    （接入调度器、503 满载响应、HTTP 线程池定容、停止顺序）、`src/config.{h,cpp}` 与
    `src/main.cpp`（`OJ_JUDGE_QUEUE_CAPACITY` 读取与校验）、`CMakeLists.txt`。
  - 未改动前端（提交失败走既有通用错误展示，显示后端 503 文案且不自动重试）。
- 构建方式：`cmake --build build --parallel 1`（单并发，内存受限约定）。
- 回归级别：**阶段全量常规回归**（改动涉及提交/判题/调度与 HTTP 线程模型）。
- 环境：Linux，约 3.3 GiB 无 Swap；隔离临时库（`/tmp`）+ 随机端口 + 独立判题目录 +
  受控执行器/真实 g++/gcc。
- 日志：调度单元 `/tmp/opencode/m31_unit.log`、调度集成 `/tmp/opencode/m31_sched.log`、
  全量回归输出见命令记录。

## 缺陷与修复记录

| 编号 | 类型 | 触发与预期 vs 实际 | 分类 | 根因与修复 | 复测 |
|---|---|---|---|---|---|
| D-001 | 实现（编译期） | 预期 `JudgeManager::Options options = {}` 可作默认实参；实际 GCC 报 “default member initializer required before the end of its enclosing class”（嵌套结构体 + 默认成员初始化器 + 默认实参） | 实现细节（编译器限制） | `Options` 改为显式默认/带参构造函数，不再使用默认成员初始化器 | 构建通过 |
| D-002 | 测试缺陷 | 调度集成测试多线程共享同一个 `httplib::Client` 发起提交，出现响应错位/丢失（`任务 B 进入等待队列`、`停止过程中已完成任务均已持久化` 等失败），服务端本身行为正确 | 测试缺陷（客户端非线程安全误用） | 每个并发请求线程使用独立 `httplib::Client`；重构后 48/48 断言通过 | S10–S16 全部通过 |

> D-002 为测试夹具误用导致的假失败，修正后未再出现；D-001 为编译期实现细节，无运行时影响。
> 未发现真实调度实现缺陷。

## 汇总与验证边界

- 全量 CTest 测试项 **29**，通过 **29**，失败 **0**，跳过 **0**，均实际执行；总耗时约 125s。
- 新增调度单元测试 **11** 项、调度集成测试 **7 场景 / 48 项断言**，全部通过。
- 已实现并验证：
  - worker 数量规则与 CPU 不可获取时的兜底；同步屏障证明真实并发且活动数不超上限。
  - 有界等待队列（容量只计等待任务）、满载立即 503、并发入队不突破容量、未接收不落库不计次。
  - 每任务独立结果通道、异常隔离、worker 恢复；已接收任务仅持久化一次。
  - 提交接口仍同步返回，AC/WA/CE/SYSERR 响应与既有约定兼容（`submit_api` 回归通过）。
  - 真实 C++17/C11 并发判题结果正确、子进程回收互不干扰（`waitpid(-1)` 无遗留）。
  - 判题繁忙/队列满载时健康检查与题目查询仍可响应（HTTP 线程池定容为 worker+容量+8）。
  - 排队时间不计入 `runtime_ms`、不误判 TLE；并发同题计数正确、首次 AC 取最早原提交时间。
  - 正常停止：停止接收、排空已接收任务、回收 worker，数据库关闭顺序安全。
- 未验证 / 未在本阶段实现（明确不标记为完成）：
  - M3.2 的 watchdog 全局 60s 硬上限与强制终止、编译/运行更完整的进程控制；
  - M3.3 的 tmpfs 目录、`setrlimit`、seccomp-bpf 沙箱与内存限制；
  - M3.4 的 ASan/UBSan、完整 AC/WA/CE/TLE/RE/MLE/SYSERR 分类与内存采集；
  - M3.6 的 Rejudge；M4 的提交历史/排行榜/CodeMirror 等。
  - 停止时排空已接收任务可能等待较久（受现有单次判题保护超时约束），强制终止未实现。
  - 未在真实多核压力（数十人同时提交）下做长时间稳定性压测；并发正确性以受控同步测试
    与全量回归证明，非实测吞吐基准。
