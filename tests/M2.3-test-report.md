## 失败项记录（7.2）

### F-1（已修复，本轮复测通过）：含空格标签场景的测试预期错误
- 清单编号：T-014；任务/功能：标签完整匹配（含空格标签）。
- 测试用例：`tests/integration/test_problem_list_query.cpp: test_tag_internal_space_match`。
- 涉及业务函数：`oj::ProblemStore::query`（`src/db/problems.cpp:162`，标签条件 `instr(','||tags||',', ?)`，错误指向 `src/db/problems.cpp:43` 的 `build_where`）。
- 触发输入/前置：题目 tags 为 `two`（P2）与 `two,three`（P3），查询 `tag=two`。
- 预期（测试原写法）：仅命中 P2，共 1 条。
- 实际（修复前）：共 2 条（P2、P3）。
- 失败断言/日志：`[FAIL] tag=two 仅命中单词标签（不误配 two words）`，见 `/tmp/opencode/m23r_api.log:161`。
- 问题分类：**测试缺陷**（测试预期错误，非生产代码缺陷）。
- 已确认根因：`two,three` 本身包含完整标签 `two`，按「完整标签匹配」规则理应命中；这是实现声明并已由 S2 验证的正确行为，测试却错误地假定 P3 不应命中。
- 修复：调整测试数据（P3 改为 `three,four`）并显式新增 `extra,two` 题目，改为断言 `tag=two` 命中 `two` 与 `extra,two` 两题、不命中的 `two words`，未放宽任何业务要求。
- 复测：`test_tag_internal_space_match` 全通过；集成 143/0；全量回归 25/25。**状态：通过（修复后复测）**。
