## 失败项记录（7.2）

### F-1（已修复，本轮复测通过）：并发测试断言错误
- 清单编号：T-021；任务/功能：并发删题×提交一致性。
- 测试用例：`tests/integration/test_admin_problems_api.cpp: test_concurrent_delete_and_submit`。
- 涉及业务函数：`ProblemAdminStore::remove`（`src/db/problem_admin.cpp:188`）、`SubmitService::submit`（`src/submit/submit.cpp:141`）。
- 触发输入/前置：5 轮「提交线程 + 删除线程」同时发起。
- 预期：题目仍在（提交先完成）时为自洽态：submit=200、delete=409、submissions=1。
- 实际（修复前）：输出 `迭代 0 不一致：题目仍在 submit=200 delete=409 submissions=1`，CTest `admin_problems_api ***Failed`。
- 失败断言/日志：`!delete_ok || delete_status != 409 ...`（`!delete_ok` 恒真）；`/tmp/opencode/m21_rerun_ctest.log:215`。
- 分类：**测试缺陷**。
- 已确认根因：`delete_ok = (delete_status==200)`，else 分支同时要求 `delete_status==409`，条件自相矛盾；首次执行恰走「删除胜出」分支未暴露。
- 修复：区分 `delete_removed=(==200)` 与 `delete_rejected=(==409)`，题目仍在分支要求 `delete_rejected && submit_ok && submissions==1 && testcases>=1`。未放宽业务要求。
- 复测：直跑 3 次 174/0；全量回归 21/21 通过。**状态：通过（修复后复测）**。
